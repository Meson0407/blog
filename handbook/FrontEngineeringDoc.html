# commonjs 和 es6 模块的区别是什么？

  1. CMJ 是社区标准，ESM 是官方标准
  2. CMJ 是使用 API 实现的模块化，ESM 是使用新语法实现的模块化
  3. CMJ 仅在 node 环境中支持，ESM 各种环境均支持
  4. CMJ 是动态的依赖，同步执行。ESM 既支持动态，也支持静态，动态依赖是异步执行的。
  5. ESM 导入时有符号绑定，CMJ 只是普通函数调用和赋值

# 语法差异：

特性 CommonJS ES6 Modules(ESM)
导出语法 module.exports = {} 或 exports.xx export 关键字（具名/默认导出）
导入语法 const mod = require('path') import ... from 'path'
动态导入 原生支持（require() 可动态调用） 需用 import() 函数（返回 Promise）
顶层 await 不支持 支持（ES2022+）
严格模式 默认非严格模式 默认严格模式（无法关闭）
// CommonJS
// 导出
module.exports = { a: 1 };
exports.b = 2;

// 导入
const mod = require('./mod');
const { a, b } = require('./mod');

// ES6 Modules
// 导出
export const c = 3;
export default { d: 4 };

// 导入
import defObj, { c } from './mod.mjs';
import * as all from './mod.mjs';

# 加载机制差异

特性 CommonJS ES6 Modules(ESM)
加载时机 运行时同步加载（阻塞执行） 编译时静态分析（异步加载）
模块解析 动态路径解析（可拼接字符串） 静态路径解析（必须明确路径）
缓存机制 模块加载后缓存结果 模块单例化（同一 URL 仅加载一次）
循环依赖处理 部分支持（可能拿到未初始化的导出） 通过绑定引用处理（更安全）
// CommonJS（问题示例）
// a.js
exports.loaded = false;
const b = require('./b');
console.log('在 a 中，b.loaded =', b.loaded); // 输出 false
exports.loaded = true;

// b.js
exports.loaded = false;
const a = require('./a');
console.log('在 b 中，a.loaded =', a.loaded); // 输出 false
exports.loaded = true;

// ES Modules（正确处理）
// a.mjs
import { bLoaded } from './b.mjs';
export let aLoaded = false;
console.log('在 a 中，bLoaded =', bLoaded); // 输出 false
aLoaded = true;

// b.mjs
import { aLoaded } from './a.mjs';
export let bLoaded = false;
console.log('在 b 中，aLoaded =', aLoaded); // 输出 false
bLoaded = true;

# 运行环境支持

环境 CommonJS ES6 Modules(ESM)
Node.js 原生支持 需 .mjs 扩展名 或 package.json 中设置 "type": "module"
浏览器 不支持 原生支持（需 <script type="module">）
Bundlers 通过工具转换 原生支持（Webpack/Rollup 等默认处理 ESM）

# 核心设计理念

维度 CommonJS ES6 Modules(ESM)
设计目标 服务端模块化（Node.js 早期方案） 浏览器/服务端统一模块化标准
依赖关系 运行时确定（动态加载） 编译时确定（静态分析）
Tree Shaking 不支持（导出对象动态属性） 支持（明确导出引用）
性能优化 同步加载影响启动速度 异步加载 + 预解析优化

# export 和 export default 的区别是什么？

# 核心区别

特性 export (命名导出) export default (默认导出)
导出方式 可导出多个具名成员 只能导出一个默认成员
导入语法 必须用 {} 包裹且名称一致 无需 {}，可自定义名称
模块标识 导出的是变量/函数的绑定引用 导出的是值（可能被覆盖）
适用场景 导出多个工具函数/常量 导出模块的主要功能/单一实体

# 代码示例对比

  1. 基本用法：
// 📁 utils.js
// 命名导出 (export)
export const PI = 3.1415;
export function sum(a, b) { return a + b; }

// 默认导出 (export default)
export default class Calculator { /* ... */ }

// 导入方式对比
// 命名导入
import { PI, sum } from './utils.js';

// 默认导入（可任意命名）
import MyCalc from './utils.js'; // Calculator 类
  1. 混合导出
// 📁 config.js
export const API_KEY = '123';
export default { timeout: 5000 };

// 导入混合导出
import conf, { API_KEY } from './config.js';
// conf → { timeout: 5000 }
// API_KEY → '123'

# 关键差异详解

  1. 导出数量限制:
  • export：可多次使用，导出多个成员

export const name = 'Alice';
export const age = 25;
  • export default：同一模块只能使用一次
// ❌ 错误：重复默认导出
export default class User {};
export default function() {}; // 报错
  1. 导入时的绑定关系:
  • 命名导出 (export)：导入的是动态绑定（修改导出值会同步影响导入值）
// 📁 counter.js
export let count = 0;
setTimeout(() => { count = 10 }, 1000);

// 📁 main.js
import { count } from './counter.js';
console.log(count); // 初始值 0
setTimeout(() => console.log(count), 2000); // 2秒后输出 10
  • 默认导出 (export default)：导出的是值的拷贝（类似 CommonJS 的 module.exports）
// 📁 data.js
let value = 1;
export default value;
setTimeout(() => { value = 2 }, 1000);

// 📁 main.js
import val from './data.js';
console.log(val); // 1（不会变成2）
  1. 重命名规则
  • 命名导出：必须使用 as 重命名
import { PI as 圆周率 } from './utils.js';
  • 默认导出：自动重命名
import 任意合法变量名 from './module.js';

# 常见问题解答

  1. 能否同时使用两种导出？
// ✅ 合法写法
export const version = '1.0';
export default function main() {};
  1. 如何导入所有命名导出？
import * as Utils from './utils.js';
// Utils.PI, Utils.sum
  1. 默认导出的本质是什么？
// 以下两种写法等价：
export default function() {};
// 等同于
function fn() {};
export { fn as default };

# 特殊注意事项

  1. Node.js 兼容性：
// 在 Node.js 中使用 ESM 默认导出
import MyModule from './module.js'; // 正确
const MyModule = require('./module.js'); // 默认导出在 require 中是 module.exports.default
  1. Webpack 优化：
  • 命名导出 (export) 支持 Tree Shaking（自动删除未使用代码）
  • 默认导出 (export default) 不利于静态分析优化
