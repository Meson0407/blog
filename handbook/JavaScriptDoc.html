# for...of 和 for...in 的区别

for...in 语句迭代一个对象的所有可枚举字符串属性（除 Symbol 以外），包括继承的可枚举属性。
for...of 语句迭代一个可遍历（iterable）对象的成员。

for...in 遍历的是数组的索引
for...of 遍历的是数组的元素

for...in 更适合遍历对象，当然也可以遍历数组
for...of 适用遍历数/数组对象/字符串/map/set等拥有迭代器对象（iterator）的集合，但是不能遍历对象，因为没有迭代器对象，但如果想遍历对象的属性，你可以用for in循环（这也是它的本职工作）或用内建的Object.keys()方法

总结

  1. for in遍历的是数组的索引（即键名），而for of遍历的是数组元素值
  2. for in总是得到对象的key或数组、字符串的下标
  3. for of总是得到对象的value或数组、字符串的值

# 箭头函数和普通函数的区别

  1. 语法差异

  • 普通函数：使用 function 关键字定义

    function funcName(params) {
  // 函数体
}

  • 箭头函数：使用 => 定义，可省略 function 和 return (单行时)

    const funcName = (params) => {
  // 函数体
};
  1. this指向

  • 普通函数：this 是动态的，取决于调用方式，谁调用就指向谁。

    const obj = {
  value: 42,
  getValue: function() {
      return this.value; // this 指向 obj
  }
};
obj.getValue(); // 42

  • 箭头函数：this 是词法的， 继承自外层作用域（定义时的上下文）。

    const obj = {
  value: 42,
  getValue: () => {
      return this.value; // this 指向全局对象（如 window）
  }
};
obj.getValue(); // undefined（严格模式下报错）
  1. arguments 对象

  • 普通函数：arguments 对象包含函数调用的所有参数。

      function sum() {
      return Array.from(arguments).reduce((a, b) => a + b);
  }
  sum(1, 2, 3); // 6

  • 箭头函数：箭头函数没有自己的 arguments 对象，需用剩余参数（...args）。

    const sum = (...args) => {
    return args.reduce((a, b) => a + b);
};
sum(1, 2, 3); // 6
  1. 构造函数能力
  • 普通函数：可以作为构造函数使用，通过 new 关键字调用。
    function Person(name) {
    this.name = name;
}
const person = new Person('Alice');
  • 箭头函数：不能作为构造函数使用，不能使用 new 关键字调用。
    const Person = (name) => {
    this.name = name; // 错误，箭头函数没有自己的 this
};
const person = new Person('Alice'); // 错误，不能作为构造函数使用
  1. 方法适用性

  • 普通函数：适用于对象方法，适合作为对象方法（可通过 this 访问对象属性）。

    const counter = {
  count: 0,
  increment: function() {
      this.count++; // this 指向 counter
  }
};
counter.increment();

  • 箭头函数：不适合作为对象方法（this 不会指向对象）。

      const counter = {
      count: 0,
      increment: () => {
          this.count++; // this 指向全局对象
      }
  };
  counter.increment(); // 无效（严格模式下报错）
  1. 其他区别
特性 普通函数 箭头函数
prototype 有 无
生成器函数 支持（function*） 不支持
super 和 new.target 支持 不支持（继承外层作用域的）
  1. 总结

  • 使用普通函数：

    • 需要动态 this（如对象方法、事件处理器）。
    • 需要构造函数或生成器函数。
    • 需要访问 arguments 对象。

  • 使用箭头函数：

    • 需要词法 this（如回调函数、React 组件方法）。
    • 需要更简洁的语法（如数组操作 map/filter）。
    • 避免 this 绑定的意外行为。

# new 操作符是什么，做了什么？

  • new 操作符 用来创建一个 给定构造函数的实例对象
function Person(name, age) {
    this.name = name;
    this.age = age;
}

Person.prototype.sayName = function () {
    console.log(this.name);
}

const p = new Person('张三', 20);
p.sayName();

// new 通过构造函数创建的p实例对象 可以访问构造函数内部的属性和方法，也可以访问构造函数原型上的属性和方法。（即实例对象和构造函数 通过原型链 连接了起来）
  • 如果在构造函数中加返回值，并且设置为返回原始类型，这个返回值没有作用
function Test(name) {
    this.name = name;
    return 1;
}

const t = new Test('张三')
console.log(t.name); // 张三
  • 如果返回值为对象类型，那么返回值会覆盖实例对象，调用t2.name会返回 undefined，因为返回的对象上 不存在 name 属性
function Test2(name) {
    this.name = name;
    return { age: 10 }
}

const t2 = new Test2('张三')
console.log(t2.name); // undefined
  • new 操作符具体流程：
  1. 创建一个空对象
  2. 将空对象的原型指向构造函数的原型
  3. 将构造函数内部的this 指向这个空对象
  4. 根据构造函数返回类型判断，如果是 原始类型，就返回空对象，如果是对象类型，就返回这个对象
  • 手写 new 操作符
function myNew(fn, ...args) {
    // 1.创建空对象
    const obj = {};
    // 2.将空对象的原型指向构造函数的原型
    obj.__proto__ = fn.prototype;
    // 3.将构造函数的this指向空对象
    const res = fn.apply(obj, args)
    // 4. 根据类型判断，如果是对象类型，返回这个对象，否则返回创建的空对象
    return res instanceof Object ? res : obj;
}

// 测试
function Test3(name, age) {
    this.name = name;
    this.age = age;
}

Test3.prototype.sayName = function() {
    console.log('自定义 new ：', this.name);
}

const t3 = myNew(Test3, '张三', 20);
t3.sayName();
console.log(t3.age);

# defer 和 async 的区别

在 JavaScript 中，defer 和 async 是 <script> 标签的两个属性，用于控制脚本的加载和执行行为。以下是它们的核心区别和适用场景：

  1. 默认行为（无 defer 和 async）:

    • 加载：同步加载脚本，阻塞 HTML 解析。
    • 执行：脚本下载完成后立即执行，继续阻塞 HTML 解析。

  2. async:

    • 加载：异步加载脚本，不阻塞 HTML 解析。
    • 执行：脚本下载完成后立即执行，此时可能中断 HTML 解析。
    • 执行顺序：多个 async 脚本的执行顺序不可控（谁先下载完谁先执行）。
    • 适用场景：独立脚本（如统计代码、广告脚本），不依赖 DOM 或其他脚本。
        <script src="script1.js" async></script>
    <script src="script2.js" async></script>
    <!-- script1 和 script2 的执行顺序无法保证 -->

  3. defer:

    • 加载：异步加载脚本，不阻塞 HTML 解析。
    • 执行：脚本在 HTML 解析完成后、DOMContentLoaded 事件触发前 按顺序执行。
    • 执行顺序：多个 defer 脚本严格按文档中的顺序执行。
    • 适用场景：依赖 DOM 的脚本，或需要按顺序执行的脚本（如库文件+业务代码）。
        <script src="library.js" defer></script>
    <script src="app.js" defer></script>
    <!-- 先执行 library.js，再执行 app.js -->

  4. 执行时机：

    • 遇到默认 <script> → 暂停解析，加载并执行脚本 → 恢复解析
    • 遇到 async 脚本 → 后台加载，加载完立即执行（可能中断解析）
    • 遇到 defer 脚本 → 后台加载，延迟到解析完成后按顺序执行

  5. 注意事项：

    • 同时使用 async 和 defer 若同时设置，浏览器会优先使用 async，忽略 defer。

    • 内联脚本无效 async 和 defer 仅对带有 src 的外部脚本有效，内联脚本（无 src）会忽略这两个属性。

    • 动态插入的脚本 通过 JavaScript 动态插入的 <script> 默认行为类似 async，可通过 script.async = false 强制同步。

  6. 对比总结：

特性 默认行为 async defer
加载行为 同步加载，阻塞解析 异步加载，不阻塞解析 异步加载，不阻塞解析
执行时机 立即执行，阻塞解析 下载完成后立即执行 HTML 解析完成后顺序执行
执行顺序 按文档顺序执行 不可控（先下载完先执行） 严格按文档顺序执行
依赖 DOM 需确保 DOM 已解析 可能导致 DOM 未就绪 DOM 已就绪
适用场景 无特殊需求 独立脚本（如统计代码） 依赖 DOM 或有顺序要求的脚本

# 事件循环的理解

JavaScript 是单线程，同一时间只能做一件事，但并不意味着单线程会阻塞，而实现单线程非阻塞的方法就是事件循环。

事件循环是一种机制，它允许 JavaScript 在执行过程中处理异步任务，而不会阻塞主线程。它通过将异步任务放入任务队列中，然后按照一定的顺序执行，从而实现了非阻塞的效果。

一、事件循环的主要组成部分包括：

  1. 调用栈（Call Stack）：用于存储当前正在执行的函数和其上下文。
  2. 任务队列（Task Queue）：用于存储异步任务，包括宏任务（如 setTimeout、setInterval）和微任务（如 Promise 的 then 回调）。
  3. 事件循环（Event Loop）：负责从任务队列中取出任务并执行。

二、事件循环的工作流程如下：

  1. 当 JavaScript 执行到异步任务时，会将任务放入任务队列中。
  2. 事件循环会不断地检查调用栈和任务队列。
  3. 如果调用栈为空，事件循环会从任务队列中取出一个任务并放入调用栈中执行。
  4. 执行完毕后，事件循环会继续检查任务队列，重复步骤 3。
  5. 这个过程会一直持续，直到任务队列中没有任务为止。

事件循环的实现方式因浏览器而异，但基本原理是一致的。在浏览器中，主线程负责执行JavaScript代码，而事件循环则负责处理异步任务。主线程执行完同步任务后，会检查任务队列中是否有任务，如果有，则将任务放入主线程执行。主线程执行完任务后，会检查任务队列中是否有任务，如果有，则将任务放入主线程执行，直到任务队列为空。

三、想象一个快餐店厨房工作流程：

  1. 主厨（调用栈 Call Stack）：只能同时处理一道菜（同步代码）
  2. 订单队列（任务队列 Task Queue）：异步任务像待处理的订单
  3. 微波炉（Web API 线程池）：处理定时器、网络请求等耗时操作
  4. 经理（事件循环 Event Loop）：监控主厨和订单队列

四、关键概念分解：

  1. 同步代码执行（主厨直接做菜）
console.log('🍔 做汉堡'); // 立即执行
console.log('🍟 炸薯条');  // 立即执行

➔ 输出顺序：🍔 → 🍟

  1. 异步代码处理（订单队列）
console.log('开始点餐');
setTimeout(() => { console.log('⌛ 定时器汉堡') }, 0);
Promise.resolve().then(() => { console.log('🔥 优先薯条') });
console.log('结束点餐');

➔ 输出顺序：开始点餐 → 结束点餐 → 🔥 优先薯条 → ⌛ 定时器汉堡

  1. 执行流程：

阶段 1：处理同步任务

步骤 调用栈 Web API 微任务队列 宏任务队列 输出
1 main()
2 console.log('开始点餐') "开始点餐"
3 setTimeout(...) 定时器开始计时
4 Promise.resolve() [回调]
5 console.log('结束点餐') "结束点餐"

阶段 2：处理微任务

步骤 调用栈 Web API 微任务队列 宏任务队列 输出
6 执行微任务回调 [] [定时器回调] "🔥 优先薯条"

阶段 3：处理宏任务

步骤 调用栈 Web API 微任务队列 宏任务队列 输出
7 定时器回调执行 [] "⌛ 定时器汉堡"

五、微任务、宏任务对比：

⼀个需要异步执⾏的函数，执⾏时机是在主函数执⾏结束之后、当前宏任务结束之前

常⻅的微任务有：

  • Promise.then()
  • MutationObserver
  • process.nextTick()

常⻅的宏任务有：

  • setTimeout
  • setInterval
  • setImmediate
  • requestAnimationFrame
  • I/O
  • UI rendering

# this的指向有哪几种？

  1. 默认绑定（独立函数调用）

    规则：函数独立调用时，非严格模式下 this 指向全局对象（浏览器中是 window，Node.js 中是 global），严格模式下为 undefined。

    function showThis() {
    console.log(this); 
}

showThis(); // 浏览器中输出 window（非严格模式）
// 严格模式 ("use strict") 下输出 undefined

  2. 隐式绑定（对象方法调用）

    规则：当函数作为对象的方法调用时，this 指向调用该方法的对象。

    const user = {
    name: "Alice",
    greet() {
        console.log(this.name); // 输出 "Alice"
    }
};

user.greet(); // this 指向 user 对象

    易错点：方法赋值丢失 this

    const greet = user.greet;
greet(); // 输出 undefined（此时 this 指向全局对象）

  3. 显式绑定（call/apply/bind）

    规则：通过 call()、apply() 或 bind() 强制指定 this 的指向。

    function sayHello() {
    console.log(this.name);
}

const obj = { name: "Bob" };

sayHello.call(obj);    // 输出 "Bob"（立即调用）
sayHello.apply(obj);   // 同上
const bound = sayHello.bind(obj);
bound();               // 输出 "Bob"（返回绑定后的函数）

  4. 构造函数绑定（new 调用）

    规则：使用 new 调用构造函数时，this 指向新创建的实例对象。

    function Person(name) {
    this.name = name;
}

const alice = new Person("Alice");
console.log(alice.name); // 输出 "Alice"

  5. 箭头函数（Lexical this）

    规则：箭头函数没有自己的 this，其 this 继承外层作用域的 this 值。

    const obj = {
    name: "Charlie",
    greet: () => {
        console.log(this.name); // this 指向外层（此处为全局对象）
    }
};

obj.greet(); // 输出 undefined（若全局无 name 属性）

  6. 事件处理函数

    规则：DOM 事件处理函数中，this 指向触发事件的元素。

        <button onclick="console.log(this)">点击</button>
    <!-- 点击时输出 <button> 元素 -->

# 优先级总结（从高到低）

  1. new 绑定 > 显式绑定 > 隐式绑定 > 默认绑定
  2. 箭头函数的 this 由外层作用域决定，无法被修改

# 常见问题与解决方案

场景 问题 解决方案
回调函数 this 意外指向全局 使用箭头函数或 bind()
对象方法赋值 this 丢失 使用 bind() 或在构造函数中绑定
多层嵌套函数 内部函数 this 错误 使用 const self = this 或箭头函数

# 快速判断 this 的步骤

  1. 函数是否通过 new 调用？→ 指向新对象
  2. 是否使用 call/apply/bind？→ 指向指定对象
  3. 是否为对象方法调用？→ 指向调用对象
  4. 是否是箭头函数？→ 继承外层 this
  5. 默认 → 严格模式 undefined，非严格模式全局对象

# JavaScript 中对象的属性描述符有哪些？分别有什么作用？

在 JavaScript 中，对象的属性描述符（Property Descriptors）用于精确控制对象属性的行为，包括可读性、可写性、可枚举性等。通过 Object.defineProperty() 或 Object.defineProperties() 方法可以定义或修改属性的描述符。

属性描述符分为两类：数据描述符（Data Descriptors）和 存取描述符（Accessor Descriptors）。以下是它们的核心属性和作用：

  1. 数据描述符（Data Descriptors）

    用于直接定义属性的值及其行为。

    (1) value

    • 属性的具体值

    • 默认值：undefined。

    • 示例：

      Object.defineProperty(obj, 'name', {
    value: 'Alice' // 设置属性值为 'Alice'
});

    (2) writable

    • 作用：控制属性是否可被修改。

      • true：允许赋值操作。
      • false：禁止修改属性的值（严格模式下赋值会抛出错误）。

    • 默认值：false。

    • 示例：

      Object.defineProperty(obj, 'age', {
    value: 25,
    writable: false // 禁止修改 age 的值
});
obj.age = 30; // 非严格模式下静默失败，严格模式下报错

  2. 存取描述符（Accessor Descriptors）

    通过 get 和 set 方法间接控制属性的访问和修改。

    (1) get

    • 作用：定义获取属性值时调用的函数。
    • 默认值：undefined。
    • 示例：
    Object.defineProperty(obj, 'formattedName', {
    get() {
        return this.name.toUpperCase();
    }
});
console.log(obj.formattedName); // 输出 'ALICE'

    (2) set

    • 作用：定义设置属性值时调用的函数。
    • 默认值：undefined。
    • 示例：
    Object.defineProperty(obj, 'age', {
    set(value) {
    if (value < 0) throw new Error('年龄不能为负');
    this._age = value; // 通常用内部变量存储实际值
    },
    get() { return this._age; }
});
obj.age = -5; // 抛出错误

  3. 共享属性（数据/存取描述符共有）

    以下属性对两类描述符均有效：

    (1) enumerable

    • 作用：控制属性是否可被枚举。
      • true：属性会出现在 for...in 循环和 Object.keys() 中。
      • false：属性不可枚举。
    • 默认值：false。
    • 示例：
    Object.defineProperty(obj, 'id', {
    value: 123,
    enumerable: false
});
console.log(Object.keys(obj)); // 不包含 'id'

    (2) configurable

    • 作用：控制属性是否可被删除或修改描述符。
      • true：允许删除属性或重新定义描述符。
      • false：禁止删除属性，且除 writable 从 true 改为 false 外，禁止修改其他描述符。
    • 默认值：false。
    • 示例：
    Object.defineProperty(obj, 'secret', {
    value: 'top-secret',
    configurable: false
});
delete obj.secret; // 非严格模式下静默失败，严格模式下报错

  4. 数据描述符 vs 存取描述符

描述符类型 可配置属性 互斥规则
数据描述符 value, writable 不可同时定义 get/set
存取描述符 get, set 不可同时定义 value/writable

  1. 实际应用场景

    1. 封装私有属性：

      const user = {};
let _password = '123456';
Object.defineProperty(user, 'password', {
    get() { return '******'; }, // 隐藏真实密码
    set(value) { _password = value; },
    enumerable: true
});

    2. 实现不可变对象：

      const constants = {};
Object.defineProperty(constants, 'PI', {
    value: 3.1415926,
    writable: false,
    configurable: false
});

    3. 响应式数据（如 Vue 2.x）：

      const data = { _value: 0 };
Object.defineProperty(data, 'value', {
get() { return this._value; },
set(newVal) {
    this._value = newVal;
    console.log('值已更新，触发视图渲染');
}
});

  2. 获取属性描述符

    使用 Object.getOwnPropertyDescriptor() 查看属性的描述符

    const descriptor = Object.getOwnPropertyDescriptor(obj, 'name');
console.log(descriptor);
// 输出类似：{ value: 'Alice', writable: true, enumerable: true, configurable: true }
