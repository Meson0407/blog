# html中行内元素、块级元素、行内块级元素的区别

  • 块级元素：
    1. 块级元素会独占一行，并且会自动换行。
    2. 高度，行高，外边距（margin）以及内边距（padding）都可以控制。
    3. 元素的宽度如果不设置的话，默认为父元素的宽度（父元素宽度100%）。
    4. 多个块状元素标签写在一起，默认排列方式为从上至下。
<address />
<div />
<h1 />
<h2 />
<h3 />
<h4 />
<h5 />
<h6 />
<p />
<ul />
<ol />
<li />
<table />
<tbody />
<tr />
<td />
<caption />
  • 行内元素：
    1. 不会独占一行，相邻的行内元素会排列在同一行里，直到一行排不下才会自动换行，其宽度随元素的内容而变化
    2. 高宽无效，对外边距（margin）和内边距（padding）仅设置左右方向有效 上下无效
    3. 设置行高有效，等同于给父级元素设置行高
    4. 元素的宽度就是它包含的文字或图片的宽度，不可改变
    5. 行内元素中不能放块级元素，a 链接里面不能再放链接
<span></span>
<a></a>
<strong></strong>
<em></em>
  • 行内元素：
    1. 高度、行高、外边距以及内边距都可以控制。
    2. 默认宽度就是它本身内容的宽度，不独占一行，但是之间会有空白缝隙，设置它上一级的 font-size 为 0，才会消除间隙。
<button></button>
<input />
<textarea></textarea>
<img />
  • 元素类型转换：
    display: block，定义元素为块级元素
    display: inline，定义元素为行内元素
    display: inline-block，定义元素为行内块级元素

# html中 src 和 href 的区别

# 定义与用途

  • src： 表示嵌入资源（直接引入内容到当前文档），用于需要将外部资源加载并嵌入到当前文档的标签中。
<script src="app.js">：加载并执行 JavaScript 文件。  
<img src="image.jpg">：嵌入图像。  
<iframe src="page.html">：嵌入另一个页面。
  • href：表示关联资源（建立当前文档与其他资源的链接），用于需要引用外部资源但不直接嵌入的标签中。
<a href="page.html">：链接到另一个页面。
<link href="style.css">：关联 CSS 样式表。
<link href="icon.ico" rel="icon">：关联网站图标。

# 加载行为

  • src: 浏览器会立即加载并处理资源（如执行脚本、显示图片）。例如：img src="image.jpg" 会直接下载并显示图片。
  • href: 浏览器会根据上下文按需加载资源（如点击链接时加载页面、自动加载 CSS 样式表）。例如：a href="page.html" 只有用户点击时才会加载目标页面。

# 总结

  • src: 嵌入资源（内容直接影响当前文档）。
  • href: 关联资源（建立链接，不直接影响当前文档）。

# 浏览器如何解析 css 选择器？

  1. 解析流程概述

    浏览器解析 CSS 选择器的过程分为两大阶段：

    1. CSS 解析：将 CSS 代码转换为 CSSOM（CSS Object Model）。
    2. 选择器匹配：遍历 DOM 树，将 CSS 规则中的选择器与 DOM 节点匹配。

  2. 解析方向：从右向左匹配

    浏览器采用从右向左解析 CSS 选择器，以提高匹配效率：

    • 示例：选择器 .nav li a#home 的解析顺序：

      1. 先匹配所有 a#home 元素（最右端的选择器）。
      2. 向上检查父元素是否为 li。
      3. 再检查祖先是否包含 .nav 类。

    • 优点：快速过滤无关元素，减少无效匹配。

  3. 选择器优先级与匹配效率

    不同类型的选择器对解析性能的影响不同：

    选择器类型 解析效率 原因
    ID 选择器 (#id) 最高 直接通过哈希表查找，时间复杂度 O(1)
    类选择器 (.class) 高 通过类名索引，但需遍历同一类所有元素
    标签选择器 (div) 中 需遍历所有同名标签
    通用选择器 (*) 最低 强制遍历所有 DOM 节点
    后代选择器 (a b) 低 递归遍历父节点，层级越深效率越低

  4. 关键优化策略

    (1) 减少选择器层级

    • 低效：body .container ul li a.button
    • 优化：直接使用 .button（若类名唯一）

    (2) 避免通配符和属性选择器

    • 低效：[data-role="tab"]、div *
    • 优化：使用类名或 ID 替代

    (3) 优先使用类选择器

    • 类名可复用，且浏览器通过预索引加速匹配

    (4) 避免频繁使用后代选择器

    • 后代选择器 (parent child) 需要递归遍历父节点

  5. 浏览器底层实现

    现代浏览器通过以下技术加速选择器匹配：

    1. 哈希索引：对 ID、类名、标签名建立哈希表，直接定位元素。
    2. 规则预过滤：将 CSS 规则按选择器类型分组（如 ID 规则、类规则等）。
    3. 惰性匹配：仅匹配当前视口内或即将渲染的 DOM 节点。

# 浏览器同源策略

浏览器同源策略（Same-Origin Policy）是浏览器为了保障用户信息安全而实施的核心安全机制，它限制不同源的网页脚本或资源之间的跨域访问。以下是其核心要点及实际影响

  1. 同源的定义

两个 URL 的以下三部分完全一致时，视为同源：

  • 协议（Protocol）：如 http vs https
  • 域名（Domain）：如 example.com vs sub.example.com
  • 端口（Port）：如 80（默认） vs 8080

示例：

  • https://example.com/page 与 https://example.com/api → 同源（协议、域名、端口均相同）
  • http://example.com 与 https://example.com → 不同源（协议不同）
  • example.com:80 与 example.com:8080 → 不同源（端口不同）
  1. 同源策略的限制范围

同源策略主要限制以下行为：

受限操作 说明
AJAX/Fetch 请求 默认禁止跨域请求（除非服务器配置 CORS）
DOM 访问 禁止跨域页面通过 iframe 访问彼此的 DOM（如获取表单内容）
Cookie/LocalStorage 禁止跨域读取或修改其他源的 Cookie、Web Storage 数据
IndexedDB 跨域无法直接访问其他源的数据库
  1. 绕过同源策略的合法方式

虽然同源策略是默认限制，但可通过以下方式安全地实现跨域交互：

(1)CORS（跨源资源共享）

  • 原理：服务器通过响应头（如 Access-Control-Allow-Origin）声明允许的源。
  • 示例：
Access-Control-Allow-Origin: https://trusted-site.com
Access-Control-Allow-Methods: GET, POST

(2)JSONP（已逐渐淘汰）

  • 原理：利用 <script> 标签的跨域特性，通过回调函数获取数据。
  • 代码示例：
<script src="https://api.example.com/data?callback=handleData"></script>
<script>
  function handleData(data) { console.log(data); }
</script>

(3)代理服务器

  • 原理：将跨域请求转发到同源的后端代理，由代理请求目标资源。
  • 应用场景：本地开发时通过 Webpack DevServer 代理解决跨域问题。

(4)document.domain（仅限主域相同）

  • 原理：通过设置 document.domain 为相同主域（如 example.com），允许子域间通信。
  • 限制：仅适用于协议和端口相同的情况。
  1. 实际开发中的常见场景

(1)前端与后端分离部署

  • 问题：前端部署在 https://frontend.com，后端 API 在 https://api.backend.com。
  • 解决方案：后端配置 CORS 允许 frontend.com 的跨域请求。

(2)第三方嵌入组件

  • 问题：在 https://your-site.com 中嵌入第三方服务（如地图、支付）的 iframe。
  • 解决方案：使用 postMessage API 实现安全跨域通信。

(3)本地开发跨域

  • 问题：本地前端运行在 http://localhost:3000，请求后端 http://localhost:8080。
  • 解决方案：配置开发服务器代理，或后端启用 CORS 允许本地源。
  1. 安全意义

同源策略通过限制跨域交互，有效防御了以下攻击：

  • CSRF（跨站请求伪造）：恶意网站诱导用户发起跨域请求（如转账）。
  • XSS（跨站脚本攻击）：阻止攻击者窃取其他源的 Cookie 或 DOM 数据。
  • 数据泄露：防止敏感信息（如用户隐私）被第三方脚本非法获取。

# 介绍下重绘和重排（repaint & reflow），以及如何进行优化

重绘（Repaint）：当元素样式的改变不影响其在文档流中的位置时（如修改颜色、背景、边框等），浏览器仅重新绘制受影响区域的像素。
重排（Reflow）：当元素的布局属性（如尺寸、位置、显示/隐藏）发生改变时，浏览器需要重新计算元素的几何属性，并更新整个或部分页面布局。

关键区别：

  • 重排必然导致重绘，但重绘不一定触发重排。
  • 重排的成本远高于重绘（可能引发连锁反应）。

触发重排的常见操作：

操作类型 示例
几何属性修改 width, height, margin, padding
布局结构变化 添加/删除 DOM 节点、元素位置改变
获取布局属性 offsetTop, scrollWidth, clientHeight
窗口尺寸变化 window.resize 事件
字体或内容变化 文本内容修改、字体大小调整

触发重绘的常见操作：

操作类型 示例
非几何样式修改 color, background, visibility
视觉效果调整 box-shadow, outline, border-radius

性能优化策略：

  1. 减少重排次数：

  • 合并 DOM 操作：

    使用 documentFragment 或离线 DOM 进行批量修改，减少触发多次重排。

    const fragment = document.createDocumentFragment();
for (let i = 0; i < 100; i++) {
    const div = document.createElement('div');
    fragment.appendChild(div);
}
document.body.appendChild(fragment); // 仅一次重排

  • 隐藏元素后再修改：

    将元素设为 display: none，修改完成后再显示。

    const element = document.getElementById('target');
element.style.display = 'none';
// 批量修改样式...
element.style.display = 'block';
  1. 避免强制同步布局（Layout Thrashing）

  • 避免在循环中交替读写布局属性：

    读取布局属性（如 offsetHeight）会强制浏览器立即重排以确保数据准确。

    // 错误示例：强制同步布局
for (let i = 0; i < elements.length; i++) {
    elements[i].style.width = elements[i].offsetWidth + 'px'; 
}

// 优化：先读取，后修改
const widths = elements.map(el => el.offsetWidth);
elements.forEach((el, i) => {
    el.style.width = widths[i] + 'px';
});
  1. 使用 CSS 优化
  • 优先使用 transform 和 opacity：

这两个属性可通过 GPU 加速，避免触发重排和重绘（在合成层处理）。

.animate {
  transform: translateX(100px); /* 使用 transform 替代修改 left */
  opacity: 0.5;
}
  • 使用 will-change 提示浏览器：

提前声明可能变化的属性，帮助浏览器优化渲染。

.element {
  will-change: transform, opacity;
}
  • 避免使用 CSS 表达式：

calc() 等复杂表达式可能频繁触发重排。

  1. 布局与渲染优化

  • 使用 Flexbox 或 Grid 布局：

    现代布局模型（如 Flexbox）比传统浮动布局更高效，减少复杂嵌套导致的重排。

  • 避免频繁操作内联样式：

    通过切换 CSS 类名批量修改样式，而非逐个修改内联样式。

        // 优化：使用 classList
    element.classList.add('active-style');
  1. 工具检测与分析

  • Chrome DevTools：

    • Performance 面板：录制页面操作，查看重排（Layout）和重绘（Paint）耗时。
    • Rendering 工具：开启 Paint flashing，高亮显示重绘区域。

示例对比：优化前后性能差异：

未优化代码：

const element = document.getElementById('box');
for (let i = 0; i < 100; i++) {
  element.style.width = element.offsetWidth + 1 + 'px'; // 强制同步布局
}

结果：触发 100 次重排，页面卡顿。

优化后代码：

const element = document.getElementById('box');
const initialWidth = element.offsetWidth; // 先读取
for (let i = 0; i < 100; i++) {
  element.style.width = initialWidth + i + 'px'; // 批量修改
}

结果：仅触发 1 次重排，性能显著提升。

总结：

  • 核心原则：最小化布局计算次数，减少渲染管道的无效触发。
  • 关键步骤：批量操作、避免强制同步布局、优先使用合成层属性。
  • 工具辅助：通过浏览器开发者工具精准定位性能瓶颈。

通过合理应用上述策略，可有效降低页面渲染的 CPU/GPU 负载，提升用户体验。

# 总结一下 DOM 中如何注册事件和移除事件

一、注册事件三种方式：

  1. HTML内联属性（不推荐）：
<button onclick="handleClick()">点击</button>
  • 特点：
    • 直接写在 HTML 中，绑定全局函数
    • 只能绑定一个处理函数
    • 难以维护，避免使用
  1. DOM 属性绑定
const btn = document.querySelector('button');
btn.onclick = function() { 
  console.log('点击事件1');
};
  • 特点：
    • 通过元素属性（如 onclick）绑定
    • 会覆盖同事件之前的绑定
    • 仅支持冒泡阶段
  1. addEventListener（推荐）
function handleClick() {
  console.log('点击事件');
}

btn.addEventListener('click', handleClick, { 
  capture: false, // 是否捕获阶段触发（默认false）
  once: true      // 是否只触发一次（默认false）
});
  • 特点：
    • 可绑定多个处理函数
    • 支持捕获/冒泡阶段控制
    • 支持配置项（如 once、passive）

二、移除事件的 3 种方式：

  1. 移除 HTML 内联事件
<button onclick="null">移除事件</button>
  1. 移除 DOM 属性绑定
btn.onclick = null; // 直接覆盖为 null
  1. removeEventListener
btn.removeEventListener('click', handleClick, false); // 参数必须与注册时一致

三、核心对比与注意事项

方式 多监听器支持 捕获阶段支持 匿名函数处理 推荐指数
HTML 内联属性 ❌ ❌ ❌ ⭐
DOM 属性绑定 ❌ ❌ ❌ ⭐⭐
addEventListener ✅ ✅ ✅ ⭐⭐⭐

关键注意事项

  1. 匿名函数陷阱
// 错误示例：无法移除
btn.addEventListener('click', () => console.log('点击'));
btn.removeEventListener('click', () => console.log('点击')); // 无效

// 正确做法：保存函数引用
const handler = () => console.log('点击');
btn.addEventListener('click', handler);
btn.removeEventListener('click', handler);
  1. 事件配置一致性

若注册时使用了 { capture: true }，移除时需对应：

btn.addEventListener('click', handler, { capture: true });
btn.removeEventListener('click', handler, true); // 必须明确 capture 值

  1. 性能优化

    • 使用 once: true 自动移除一次性事件
    • 及时移除不再需要的事件监听，避免内存泄漏

四、高级用法：事件委托

通过父元素代理子元素事件，减少监听器数量：

document.getElementById('list').addEventListener('click', function(e) {
  if (e.target.tagName === 'LI') {
    console.log('子项被点击:', e.target.textContent);
  }
});

总结

  • 最佳实践：统一使用 addEventListener + 具名函数引用。
  • 性能关键：及时移除无用监听、善用事件委托。
  • 兼容性：现代浏览器均支持 addEventListener，无需考虑旧版 IE 的 attachEvent。
